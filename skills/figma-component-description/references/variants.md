# Variants Filling Rules

Read only when working on the variants block. Follow the block map and SKILL.md approval cycle. These rules are being refined with the user sequentially.

## Complete combination coverage

Show every existing combination of variant properties and describe each combination individually. Enumerate the actual variants in the selected component set; do not substitute representative combinations or only describe each property axis.

Create a demonstration using the real variant and preserve its exact property names and values. For each combination, describe its purpose and conditions of use, grounded in the component and confirmed context. A separate comparison or differences section is not required. Clarify unknown purpose or usage one question at a time. Do not substitute one generic description for the individual purpose and usage of each combination.

Existing combinations are not the Cartesian product of all possible property values. Do not invent, create, or imply support for combinations absent from the source. Do not treat text overrides, boolean instance properties, or instance swaps as additional variant axes unless the source actually defines them as variant properties.

Read large variant sets in bounded batches and track coverage internally. Batching must not omit combinations or turn the output into a representative subset. Preserve the template's description-and-demonstration structure by repeating its blocks as needed; prepare the block draft for approval before writing to Figma.

Before marking the variability check complete, compare documented combinations against the source variants and verify that each has a demonstration and an individual description. This does not authorize changes to source components or to the separate states block.
