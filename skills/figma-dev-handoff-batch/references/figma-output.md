### Predictable placement and sizing labels

Apply this placement contract to the designer-prepared objects, using the live palette's typography and annotation spacing rather than inventing a universal pixel offset:

1. Preserve the objects and their placement. Work from overall width and individual-element dimensions to major blocks, padding/gaps, radii and necessary nested details. Do not annotate the overall height of a complete screen/page; measure heights of individual elements and sections instead.
2. Put width measurements above the target and height measurements to its left. Put padding against the corresponding inner edge, gaps between the measured elements and radius markers at the relevant corner. Follow an explicit supplied reference placement if it differs from these defaults.
3. Anchor measurement endpoints to actual layer boundaries in a common coordinate system. Distinguish container padding from external spacing; do not measure template geometry or visual estimates.
4. Separate nested dimensions into readable parallel lanes: details nearest the target, block dimensions farther out, overall width outermost. Avoid crossing lines, overlapping labels or ambiguous ownership.
5. Keep UI text and existing specifications unobscured. When space is tight, move the annotation to available space with an unambiguous association supported by the real tool. Record a placement/tool limitation if needed; do not shrink labels below the supplied reference size, relocate product content or replace diagrams with a numeric prose list.
6. Show the actual sizing rule, not only the current rendered number. Where a percentage width is confirmed, label the percentage and its reference explicitly: viewport or the named parent container. Include confirmed offsets/constraints when needed. Do not infer a percentage from a ratio measured at one width, equate Fill with viewport width, or present a current pixel width as a fixed requirement. If the rule is unknown, identify the value as observed and retain the rule as an open question.
7. Use confirmed Fixed/Hug/Fill, percentage and min/max information from applicable project sources or actual settings. Keep observed dimensions distinct from intended implementation behavior. Do not invent bounds or force the sizing rule to fit an instrument's default numeric label.
8. Measure one prepared representative of each equivalent construction, explicitly identify shared coverage and annotate meaningful differences on the other prepared objects. Do not duplicate the same dimensions across every state.
9. Keep numbers and sizing labels in real measurement tools. Use short Notes for construction explanations and confirmed non-obvious behavior, not numeric inventories.

### Tool selection from the supplied palette

Read the live palette's usage labels as well as component names and properties; they determine which tool belongs at each location. In the supplied palette the roles are distinguished as follows. Preserve that distinction, and use newly supplied explicit tool instructions if the palette changes. Names and visible property values below describe tool roles, not fixed node IDs, property suffixes or example measurements:


| Measurement | Example family | Treatment |
| --- | --- | --- |
| Width / individual-element height | `spec-sizelines`, `Numbers=On` | Full dimension lines, actual span and confirmed sizing rule; omit full-screen/page height |
| Radius | `spec-radius` | Marker at the measured corner, using the matching corner variant |
| Global margin / gap between major blocks | `spec-magrin` | Global spacing band in the appropriate orientation |
| Local gap within a block/component | `spec-sizelines`, `Numbers=Only` | Local spacing annotation, oriented to the measured gap; do not substitute the global spacing band |
| Internal padding | `spec-padding` | Padding band at the corresponding inner edge, with the appropriate orientation |

Inspect exposed properties once; some numbers are nested `Value` text rather than exposed properties. Use supported overrides; never detach, draw imitations or change instance-child transforms unsupported by Figma. Ask in the package if a required tool is missing. Measure target layers, not screenshots or template geometry. Anchor labels to the measured sides/corners with readable spacing. Preserve the reference palette. Arrange diagrams using known bounds; no routine screenshot/temporary QA stage.

Place exact local and library component names with already resolved links in construction. A verified common library link may accompany entries without individual links. One failed source attempt means plain original name and continuation, not more lookup or a blocking approval. Do not reproduce global library specifications.
